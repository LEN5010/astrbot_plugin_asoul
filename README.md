# astrbot_plugin_asoul

AstrBot 插件，用于查询 A-SOUL 今日 / 明日直播安排，并提供一个简短的 Bot 使用帮助入口。

同时支持轮询指定 B 站 UID 的：

- 新动态
- 新视频
- 开播信息
- 最近 3 条动态和最近 3 个视频评论区中，目标 UID 发表的新评论

并自动推送到配置白名单内、且已经被插件登记过会话来源的群聊。

## 功能

- 读取 `https://asoul.love/calendar.ics`
- 清洗指定日期的直播数据，合并同时间同内容的多人直播
- 使用 `Pillow` 本地绘制直播卡片图片
- 支持在卡片右侧展示当前场次对应成员头像
- 管理员可以将任意日期的多个节目全局标记为“特别关注”，在单日和本周卡片中展示香槟金聚光、描边及角标
- 提供 `/bot帮助` 文本帮助
- 支持轮询指定 B 站 UID 的动态 / 视频 / 直播并主动推送到白名单群
- 动态、新视频、开播和评论通知使用统一的「爱驼推送」粉白图片卡片，包含富文本、配图、作者资料和二维码
- 支持评论头部优先、后台根索引核对、变化触发楼中楼分页、SQLite 持久化检查点和逐群投递确认
- 内容轮询与评论抓取完全隔离；慢评论或单个慢 UID 不再阻塞其他 UID 的动态检查
- 视频卡片在实际发送前通过视频详情接口刷新点赞、评论和分享数；同一 BV 号缓存 5 分钟，多群推送不会重复请求

卡片中的“本条内容”表示当前动态或视频的互动数据，“UP资料”表示作者累计获赞、关注和粉丝数据。视频详情接口超时或异常时会准时使用动态页备用统计，并标注“数据暂未刷新”；`render_bilibili_cards=false` 时保持原文本格式且不会额外请求视频统计。

升级到 `v3.6.0` 不会清空已有动态游标、旧评论 KV、直播状态、作者资料缓存、群推送配置或评论 SQLite 数据，也不会删除已有任务、观察记录、通知事件和投递记录。日程特别关注使用独立 KV 保存，不修改来源 ICS 或日历缓存。`comment_target_uids` 留空时会继续沿用原 `target_uids`，避免升级后意外停止评论监控。

## 指令

### 直播查询

发送以下任一消息：

- `今日直播`
- `明日直播`
- `本周直播`

插件会返回一张直播安排图片，包含：

- 开播时间
- 主播 / 团播成员
- 直播内容
- 当前场次对应头像

说明：

- `今日直播` 查询当天直播
- `明日直播` 查询下一天直播
- 如果当天是周日，发送 `明日直播` 会返回 `还没有下周的直播排表哦`

### Bot 帮助

发送以下任一消息：

- `/bot帮助`
- `bot帮助`

返回内容为：

```text
鸣潮bot请使用【ww帮助】获取图文
自动签到请使用【ww登陆】，然后输入【ww开启自动签到】
asoul推送请使用【今日直播】、【明日直播】或【本周直播】
```

### 日程特别关注

以下指令仅限管理员使用，设置结果对所有群全局生效：

- `/日程高亮 2026-07-25`：查看当天可标记的编号日程
- `/日程高亮 2026-07-25 2`：将当天第 2 条日程设为特别关注
- `/取消日程高亮 2026-07-25 2`：取消当天第 2 条日程的特别关注
- `/日程高亮列表`：查看当前保存的全部特别关注日程
- `/取消日程高亮记录 2`：按保存列表序号移除记录，适用于来源日历已经删除的节目

同一天可以标记多个节目。序号只用于选择，保存时会使用日期、开播时间、节目内容和类型生成稳定标识，因此当天插入其他节目不会让已有标记错位。特别关注会同时显示在“今日直播”“明日直播”和“本周直播”卡片中；图片渲染失败时，纯文本结果会使用 `⭐【特别关注】` 标记。记录不会自动删除，只有管理员明确取消时才会移除。

### B站评论推送状态

管理员使用：

- `/bili_status`

该命令显示评论推送开关、登录状态、请求客户端、任务状态和目标群数量，并分别报告头部、回复变化、根索引、休眠楼层、历史补齐、请求吞吐、安全复查周期、待投递以及根评论/楼中楼最近完整核对时间。头部或某个 UID 等待过久时会显示容量告警。

## 依赖

本插件当前以本地图片渲染为主，运行环境需要：

- Python 可用
- `Pillow` 已安装
- 若启用 B 站自动播报，还需要：
  - `bilibili-api-python`
  - 异步请求库，推荐 `aiohttp`
  - `qrcode>=8.2`，用于在本地生成卡片二维码

如果 `Pillow` 不可用，直播图片无法正常生成。

其中，B 站相关能力明显依赖：

- [Nemo2011/bilibili-api](https://github.com/Nemo2011/bilibili-api)

当前以下功能直接建立在该库之上：

- B 站二维码登录
- UID 动态抓取
- UID 视频抓取
- 直播状态查询
- 最近资源评论抓取

如果没有正确安装 `bilibili-api-python`，上述 B 站功能将无法正常工作。

## 数据来源

直播数据来源：

- `https://asoul.love/calendar.ics`

插件会做内存和磁盘缓存，避免每次查询都重新拉取日历。

默认缓存 30 分钟，并会把最近一次成功拉取的 ICS 保存到本地 `temp/calendar_cache.json`。缓存过期后会优先使用 `ETag` / `Last-Modified` 做条件请求；源站返回未修改或短暂不可用时，会继续复用本地缓存以降低请求量。日历请求的 `User-Agent` 为 `asasfans`。

可在插件配置中调整：

- `calendar_cache_minutes`：直播日历缓存时间，默认 `30`，小于 `10` 会按 `10` 处理。

## 说明

- 插件按 `Asia/Shanghai` 时区处理今天 / 明天的直播
- 会过滤取消事件和全天事件
- 团播会按识别到的成员名称合并展示
- 如果本地图片绘制失败，会退回纯文本结果
- B 站主动播报只会对白名单群生效
- B 站轮询默认按 UID 错峰调度：`poll_interval_seconds` 默认 300 秒，`task_gap_seconds` 默认 20 秒
- 内容调度器会在 UID 到期后独立启动任务，同一 UID 不重入；单个 UID 最长运行 90 秒，卡片渲染和消息发送分别限制为 30 秒
- 评论抓取使用独立任务和状态域，不再持有内容轮询锁，因此长时间评论扫描不会让动态推送累积延迟数小时
- 新视频播报从动态流中识别，不再额外轮询独立视频列表
- 开播检测走直播状态批量接口，不再依赖更容易触发 412 的 `get_live_info`
- 动态、新视频和开播默认发送“图片卡片 + 可点击原链接”；只有开播通知会按现有平台规则在卡片前添加 `@全体`
- 评论通知使用同款粉白卡片，展示评论者、评论正文与配图、来源内容、评论时间、评论者资料及原文二维码；渲染失败时继续使用原有文本、配图和链接格式
- 卡片渲染失败会自动回退原有通知格式；可将 `render_bilibili_cards` 设为 `false` 紧急关闭卡片渲染
- 作者获赞、关注、粉丝等资料单独缓存 6 小时；旧缓存会立即用于卡片并在后台刷新，资料接口失败不会阻塞内容游标
- 同一条通知的卡片会在运行期复用 30 分钟，避免向多个群推送时重复渲染；插件卸载时会清理由自身创建的临时卡片
- 白名单群必须先出现过一条消息，插件才能拿到 `unified_msg_origin` 并主动推送
- `push_comment` 单独控制评论抓取，默认关闭；`comment_target_uids` 单独指定要扫描其最近资源、并为其评论创建通知的 UID，留空时兼容沿用 `target_uids`；每个 UID 仍覆盖最近 3 条非视频动态和最近 3 个视频
- 资源首次完成一页头部评论后就进入活跃状态；已有评论只写入基线，不会回放历史通知，完整历史根索引继续在后台补齐
- 头部评论每 180 秒检查一次，突发评论会继续翻页直到已观察检查点；根评论索引完整核对完成后等待 6 小时再开始下一轮
- 根评论回复数或内嵌回复指纹变化时才立即抓取对应楼中楼；回复数为 0 的楼层保持休眠，不再每 30 分钟发送一次空请求
- 有回复楼层保留容量自适应安全复查，默认从 24 小时开始，规模超过安全吞吐时自动延长；楼中楼仍会按页完整遍历
- 评论进度、已观察评论、通知事件和逐群 outbox 持久化在 SQLite；插件重启后从上次页游标继续
- 评论通知采用至少一次投递：只有某个群发送成功后才确认该群；若发送结果不确定，重试时该群可能收到重复通知
- `comment_request_interval_seconds` 可配置评论接口全局最小间隔，默认 2 秒、范围 0.5–60 秒；低于 2 秒会提高触发风控的概率。单页最长等待 20 秒；失败不会推进页游标，并按指数退避重试，最长可能延迟 12 小时
- 评论抓取按 head 50%、reply 30%、reconcile 20% 公平轮转，并在每个通道内轮转 UID；空闲通道的配额会立即借给其他通道
- 资源目录使用独立后台任务每 600 秒刷新，单次发现预算 30 秒，不再阻塞评论扫描；失败会持久化指数退避，最长 12 小时
- 资源退出最近 3+3 范围时停止扫描但保留全部持久化数据；再次进入时建立新生命周期，不会复用旧生命周期回放历史
- 内容抓取超时或发送失败也不会推进对应群的内容游标，下轮会继续重试；其他 UID 和其他群不受影响
- 评论接口仍按资源查询；插件只为 `comment_target_uids` 账号发表的评论创建通知，其他评论会记录为已观察数据以保证分页和去重完整

### 评论抓取只读验证工具

开发者可使用真实评论区验证完整分页、重启友好的检查点和事件去重。凭据 JSON 必须放在仓库外，并设置为仅当前用户可读写；不要把 Cookie 粘贴到聊天中，也不要提交到 Git：

```bash
chmod 600 /absolute/path/outside/repository/bilibili-cookie.json
python3 tools/verify_bilibili_comments.py \
  --credential-file /absolute/path/outside/repository/bilibili-cookie.json \
  --owner-uid 100 \
  --target-uid 100 \
  --oid 2003 \
  --type-value 1 \
  --resource-kind video \
  --resource-url https://www.bilibili.com/video/BV_TEST \
  --duration-seconds 900 \
  --report /tmp/asoul-comment-verification.json
```

凭据文件仅接受 `sessdata`、`bili_jct`、`buvid3`、`buvid4`、`dedeuserid` 和 `ac_time_value` 字段，至少需要 `sessdata`。工具不会调用任何 B 站写接口或 AstrBot 消息接口，只使用临时 SQLite 并写出不含凭据的本地 JSON 报告。启动后按终端中的随机标记手动发表一条一级评论和一条楼中楼回复；只有两者都被捕获、完成一次复扫且没有产生重复事件时才返回成功。
