状态模型与失败恢复

所有可恢复状态落在独立的评论日志中。抓取状态和群投递状态分离，避免一个群发送失败影响其他群或下一轮扫描。

Resource state

进入窗口

保存进入时间和资源身份。评论早于该时间只写入基线，不生成通知。

Scan state

可恢复任务

一级游标、根楼 rpid、楼中楼页码和下一次执行时间均可在重启后恢复。

Event state

已观察事件

以资源键 + rpid 去重。扫描成功持久化后才结束该分页任务。

Delivery state

群级确认

每个群独立记录待发、已发或重试时间；发送成功后才确认。

BOOTSTRAPPING -> ACTIVE -> RETIRED -> PURGED
生命周期语义
  • BOOTSTRAPPING: 记录进入时间；扫描旧评论时仅建立已见 ID 基线。
  • ACTIVE: 持续完成一级楼与楼中楼任务；新目标评论写入 outbox。
  • RETIRED: 资源离开 3+3 窗口，停止新增抓取任务；此前已捕获但未送达的事件继续重试。
  • PURGED: 所有已捕获事件均被群确认后，才清理资源的去重与抓取记录。
失败与边界规则
  • 412、429、网络和解析异常都保留当前检查点，指数退避并限制在 12 小时内。
  • 不根据单个“已知 rpid”提前停止；分页完成由持久化任务边界判定。
  • 同一秒的评论按“新”处理，优先保证至少一次，最多可能多报进入窗口前的一秒内容。
  • 发送后持久化失败视为结果不确定，下次允许重发，绝不把它标成已确认。
